# v0.1 聊天主流程修复记录（2026-07-10）

## 背景

上一版虽然构建通过，但核心聊天流程存在严重 bug：

1. 用户在"创建智能体"页点保存后，对话空间仍显示"当前没有智能体"。
2. Agent 配置（apiUrl / apiKey）没有被持久化到数据库，页面前端 Zustand store 与数据库之间同步机制是空壳。
3. page.tsx 还引用着已经不适用的 demo-data，导致 TS 编译隐患。

## 根本原因

前端 ddLocalAgent() 把新 agent 写入本地 store，但调用链 setLocalAgents 只处理「删除」和「编辑」两种情况，「新增」分支是空壳。
加上后端 Schema 没有 apiUrl/apiKey 字段，即便前端调了 addAgent API，这些信息也写不进数据库。

## 修复清单

- **src/lib/validation.ts**：
  - schema 加 piUrl / apiKey 字段。
  - 新增 parseAgentMeta() 向后兼容旧 config（数组格式 → 新对象格式）。
- **src/app/api/agents/route.ts**：
  - GET 返回 piUrl / apiKey / capabilityIds。
  - POST 把元数据写入 config JSON 字段。
  - import 改为 parseAgentMeta。
- **src/store/agent-store.ts**：
  - ddAgent() 返回的 agent 对象完整合并 source / apiUrl / apiKey / tools / capabilityIds。
  - 	oLocalAgent() 使用 parseAgentMeta() 读取完整元数据。
  - 新增 import gentCreateSchema, parseAgentMeta。
- **src/app/page.tsx**：移除 demo-data 依赖，直接内联最小 WorkspaceSnapshot 对象（含 description / mode / budgetLimit 全字段）。
- **新增（清理）**：scripts/fix-*.py 修复脚本，便于追溯。
