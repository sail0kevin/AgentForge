## 摘要

本阶段解决的不是“再增加几个功能”，而是让前六阶段已经形成的业务能力更容易维护、更不容易回归，并让发布声明与真实证据一致。

最终完成三项工作：第一，把原来同时承担状态、网络、翻译和全部页面渲染的 `workspace-app.tsx` 拆成职责明确的模块；第二，修复 Workspace 创建接口接收 `agentIds` 却不绑定 Agent 的契约错误，并增加原子性与越权测试；第三，正式把 0.1 版本交付范围定为 Web MVP，Electron 壳保留为实验入口，不把未经干净机器验证的壳描述成桌面产品。

阶段验收结果及Phase 6 Checkpoint完成后的最新回归为：TypeScript通过、全量Lint零错误零警告、单元测试59/59、隔离数据库核心E2E 24/24、Session切换E2E 1/1、SQLite与PostgreSQL Schema校验通过、生产构建通过且原NFT tracing警告已消除。

一句话解释：本阶段让项目从“功能基本可跑”进入“结构、契约、证据和发布口径能够互相对上”的状态。

## 1. 为什么必须做这一阶段

在功能快速增长时，把所有界面都放在一个文件里看起来省事，但会带来三个后果：

1. 修改知识库页面时也可能误伤聊天或设置页面；
2. 状态、接口调用和视图混在一起，审查者很难判断错误发生在哪一层；
3. 测试通过后，发布文档仍可能把实验入口写成正式能力，形成“代码能构建，但产品表述失真”的问题。

阶段7因此采用三个验收问题：

- 前端页面是否已经按职责分开？
- API声明接收的数据是否真的生效，并且失败时不会留下半成品？
- Web与Electron的交付声明是否与实际验证范围一致？

这三个问题分别对应P2-1、P2-2和P2-3。

## 2. 修改前基线

### 2.1 前端结构

修改前，`src/components/workspace/workspace-app.tsx`约1550行、73 KiB。它同时包含：

- 中英文文案；
- 页面导航和主题切换；
- Agent创建、编辑、删除；
- 聊天输入、SSE读取和消息展示；
- 知识文档上传、列出和删除；
- Tool选择；
- 数据看板；
- API Key设置；
- 多个通用UI组件。

文件并非因为“行数大”就必然错误，真正的问题是职责跨度过大：任何小改动都需要理解整个页面，增加了冲突和回归概率。

### 2.2 Workspace创建契约

创建Workspace的请求Schema允许提交 `agentIds`，但旧POST路由只创建Workspace本身，没有创建 `WorkspaceAgent`关联。调用者会收到成功响应，却得不到请求中指定的Agent。这属于静默忽略字段，比直接返回错误更危险，因为它制造了“看似成功”的错误状态。

### 2.3 Electron交付

仓库已有Electron壳和electron-builder配置，但入口依赖 `npm start`、固定3000端口和仓库工作目录。当前没有完成：

- 将数据库与密钥放入 `app.getPath("userData")`；
- 安装后自动应用migration；
- 端口冲突处理和服务健康恢复；
- 打包后Next.js服务与原生模块加载验证；
- Windows干净机器安装、启动、升级和卸载测试；
- macOS签名、公证以及Linux发行验证。

因此“能看到Electron代码”不能等价为“桌面版已交付”。

## 3. P2-1：前端职责拆分

### 3.1 拆分结果

主控制器缩减到约458行、21 KiB，保留会话状态、运行编排、Agent与文档操作。页面视图和共享定义移动到以下模块：

| 文件 | 职责 | 当前规模 |
|---|---|---:|
| `workspace-app.tsx` | 状态、生命周期、SSE和业务动作编排 | 约458行 |
| `workspace-copy.ts` | 中英文文案与Copy类型 | 约216行 |
| `workspace-chat.tsx` | 对话、Agent列表、消息和输入框 | 约120行 |
| `workspace-agent-manager.tsx` | Agent列表、创建、编辑和能力绑定 | 约94行 |
| `workspace-tools.tsx` | 能力库、知识文档和Tool选择弹窗 | 约70行 |
| `workspace-dashboard.tsx` | 运行统计、费用和Provider分布 | 约71行 |
| `workspace-settings.tsx` | API Key设置 | 约70行 |
| `workspace-shell.tsx` | 左侧导航、顶部栏、语言和主题 | 约69行 |
| `workspace-primitives.tsx` | Panel、Field、Avatar、InfoBlock | 约37行 |
| `workspace-types.ts` | 页面共享View Model类型 | 约26行 |

这不是简单地把一个大文件复制成多个文件。拆分边界遵循“一个模块对应一个用户可理解的页面职责”，类型依赖放入独立文件，避免视图模块反向依赖主控制器。

### 3.2 同步修正

拆分过程中还修复了以下遗留问题：

- 英文界面语言切换中的“中文”标签由损坏字符恢复为正常文本；
- 清理知识文档相关的乱码注释，改成简短、可维护的中文说明；
- Tool选择弹窗增加 `role="dialog"`、`aria-modal`和标题关联；
- 通知、错误、加载状态增加 `status`、`alert`和 `aria-live`语义；
- 设置页补充中英文标签、表单可访问名称和请求取消；
- Dashboard请求使用AbortController，卸载后不再回写状态。

### 3.3 为什么仍保留主控制器

没有继续把每个 `useState`机械地抽成Hook。SSE运行、Session生命周期、Store清理和消息恢复共享同一个取消边界，过早拆散会让并发关系更难理解。当前主文件只保留有共同生命周期的业务编排，后续只有在出现独立复用或测试需求时再抽取 `useManualRun`、`useKnowledgeDocuments`等Hook。

因此本次目标是“降低职责耦合”，不是追求任意的最小行数。

## 4. P2-2：Workspace与Agent原子绑定

### 4.1 服务端行为

POST `/api/workspaces`现在执行以下顺序：

1. 使用Schema验证名称、描述和 `agentIds`；
2. 拒绝空ID、超过12个ID和重复ID，返回稳定400；
3. 查询所有ID是否属于当前用户；
4. 任一ID不存在或属于其他用户时返回404；
5. 在一次Prisma嵌套创建中同时写入Workspace和WorkspaceAgent；
6. 使用 `sortOrder`保留调用者提交的Agent顺序；
7. 返回映射后的Workspace、Agent和消息DTO。

PATCH路由也改用安全解析，非法请求返回400，不再让Zod异常变成不稳定的500。

### 4.2 原子性是什么意思

“原子”可以理解为“要么全部成功，要么全部不发生”。例如提交两个Agent，其中一个不属于当前用户时，系统不会先创建一个空Workspace再报错。数据库中不会留下需要人工清理的半成品。

### 4.3 新增E2E证据

第20项核心E2E实际验证：

- 两个合法Agent按 `[第二个, 第一个]`绑定，POST和后续GET顺序一致；
- 不存在或不归属当前用户的Agent导致404，Workspace数量不增加；
- 重复Agent ID导致400，Workspace数量不增加；
- 合法请求最终只创建一个Workspace。

这项测试同时证明字段生效、顺序保持、用户隔离和失败原子性，不只是检查HTTP状态码。

## 5. P2-3：Web与Electron交付决策

### 5.1 正式决策

AgentForge 0.1的正式可交付形态是Web应用。Electron代码保留为实验性开发壳，不进入当前发布完成度，也不提供“可安装桌面版已完成”的声明。

这项决策关闭的是“交付口径不明确”，不是宣称Electron技术问题已经实现。

### 5.2 为什么选择Web优先

核心业务依赖Next.js服务端路由、Prisma、数据库migration、认证、模型凭证和流式请求。Web形态可以直接复用已经验证的运行方式；桌面形态还要额外解决服务进程、数据目录、端口、签名和升级等平台问题。当前产品价值是生成可审计的开发报告，而不是证明能够打出安装包。

### 5.3 将来重新启动桌面交付的准入条件

只有明确存在离线桌面分发需求时，才启动新的Desktop阶段，并至少完成：

1. 数据库、日志和配置迁入用户数据目录；
2. 首次启动和版本升级migration；
3. 随机可用端口、单实例锁和子进程退出回收；
4. 打包后的Next.js服务器与Prisma原生依赖验证；
5. 密钥进入系统凭证库或等效安全存储；
6. Windows干净虚拟机安装、启动、升级、卸载；
7. 若发布macOS，完成签名、公证和权限说明；
8. 形成独立安装测试记录和回滚方案。

在这些条件完成前，Electron只是一条技术探索路径。

## 6. 工程质量门关闭

### 6.1 Lint

全量 `npm run lint`为零错误、零警告。处理内容包括：

- Electron `.cjs`使用符合CommonJS入口事实的定向规则；
- `archive/**`作为历史材料，不混入活动源码质量门；
- 删除旧生成脚本中的无效变量；
- 拆分后的所有前端模块通过React Hooks和TypeScript规则。

### 6.2 构建警告

原生产构建会因为运行时数据库路径触发Turbopack NFT全仓库追踪警告。`src/lib/db.ts`现在明确把运行时数据库路径标记为非构建输入。重新构建后警告消失，构建输出只保留正常路由清单。

这里没有关闭依赖追踪本身，只排除了数据库运行时路径这一不应进入构建输入的值。

### 6.3 可访问性范围

本阶段完成关键动态状态和弹窗的语义补强，并通过Lint与真实页面E2E。尚未执行完整的WCAG 2.2 AA人工审计、键盘全流程、屏幕阅读器矩阵和颜色对比自动扫描，因此不能宣称“已获得WCAG 2.2 AA认证”。这属于发布前体验审计，而不是当前三个P2问题的虚假完成项。
