## 1. 结论

此前文档正确识别了安全、运行正确性、RAG、Tool 和前端维护性问题，但部分表述把“当前双 Agent Web MVP”当成长期产品边界，整改顺序也没有完整覆盖正式设计中的 Planner、动态报告、候选方案、交叉评审、Evaluator 和人工确认。

正式产品定位统一为：

> AgentForge 是面向 Web 项目的多智能体需求规划与开发方案生成平台。核心产物是根据用户需求动态生成、带来源与取舍依据的开发方案报告。

## 2. 保留不变的结论

- Phase 0 的密钥、`.env` 和数据库初始化整改有效；
- 运行锁、runId、超时、取消和用户隔离必须先于复杂工作流；
- 统一 RunService 是 LangGraph、Planner 和恢复能力的前置基础；
- RAG 零召回、Markdown 结构丢失和 Tool 未闭环仍需解决；
- 当前实现与目标设计必须在公开文档中明确区分。

## 3. 被校正的路线

旧路线在 RunService 后直接进入 RAG、Tool 和前端质量。新路线改为：

```text
安全与数据库
→ 运行正确性
→ RunService 与领域契约
→ Planner 与结构化输出
→ 本地知识、RAG 与 Tools
→ 候选方案、交叉评审与评价
→ Artifact 与动态报告
→ 前端质量和交付
```

## 4. 归档处理

旧版公开项目报告和旧 Phase 3～5 路线已移入[历史归档]()。带日期的代码评审继续保留在 `reviews/`，因为它仍是整改前代码事实和问题证据；其中的旧路线建议由当前整改总览替代。

## 5. 文档优先级

出现冲突时按以下顺序判断：

1. `docs/design/`：产品边界和目标架构；
2. `docs/current-status - 当前开发状态.md`：当前已经实现的事实；
3. `docs/remediation/README - 整改执行总览.md`：当前实施顺序和进度；
4. `docs/reviews/`：某个时间点的证据快照；
5. `docs/archive/`：只供历史参考。
